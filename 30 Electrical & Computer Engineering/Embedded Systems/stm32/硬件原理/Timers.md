# Timers

> [!summary] 核心结论
> 定时器的核心是**时基单元**：时钟 → 预分频器 `PSC` 降频 → 计数器 `CNT` 计数 → 与 `ARR` 比较产生溢出 → （高级定时器再经 `RCR`）产生更新事件 **UEV**。周期 = `ARR+1`，分频 = `PSC+1`。在此之上叠加通道功能：**输出比较**（`CNT` 与 `CCRx` 比较生成 PWM，周期由 ARR 定、占空比由 CCR 定）与**输入捕获**（外部边沿到来时把 `CNT` 抓进 `CCRx`，得到时间戳）。**从模式控制器**让本定时器的计数受外部/其它定时器的 `TRGI` 指挥，编码器模式与 PWM 输入测量都建立在它之上。

### 1.2 时基单元的基本结构

![[Gemini_Generated_Image_9nwnty9nwnty9nwn.jpg]]

1. 时钟源：时钟信号有两种来源 ，预分频器用于对时钟信号进行降频（时钟来源见 [[Clocks|时钟树]]）
2. 计数器：对分频后的脉冲信号进行计数（数字电路层面的实现见 [[Counters|计数器]]）
3. ARR：和计数器的值进行比较，发生溢出
4. RCR：计数器溢出一定次数后，发生更新

### 1.3 计数方式

上计数、下计数和中心对齐

![[tikz-timers-01.svg]]

- 分辨率：计时的最小间隔
- 计时周期：产生溢出的时间

### 1.4 寄存器预加载

两层寄存器：

- **预装寄存器（写入缓冲）**
- **活动寄存器（真正参与计数/比较）**

当开启预加载后，写 ARR/CCR 并不会马上影响输出，而是先写到缓冲区，等到**更新事件 UEV**（通常是计数器溢出/下溢）时，再一次性搬运到活动寄存器生效。

![[截屏2026-02-05 下午1.06.00.png]]

预分频器同样带缓冲——参数从 1 改到 2 时，新值要等下一个更新事件才真正生效：

![[image-20260124084107976.png]]

#### 1.4.1 结合 PWM 的工程理解

假设做呼吸灯 PWM：

1. 开启 `ARPE` 和 `OCxPE`
2. 主循环不断改 ARR/CCR（写的是预装层）
3. 每个更新事件到来时，硬件统一切换参数

结果：

- 周期和占空比在“周期边界”更新
- 不会出现中途折线、突刺
- 视觉上更顺滑，电机/功率负载也更稳定（详见 [[Timers#3.2 基本工作原理（PWM）|PWM 基本工作原理]]）

## 2. 自制延迟函数

### 2.1 获取当前时间

配置时基单元，实现 1ms 产生中断

```c
volatile uint32_t currentTick=0; //记录当前时间，单位ms，volatile:变量值会发生变化
```

### 2.2 实现延时函数

```c
// @简介： 延迟一段时间
// @参数 ms: 要延迟的时间 (单位ms)
void App_Delay(uint32_t ms)
{
    uint32_t expireTime = currentTick + ms; // 延迟结束的时间
    while(currentTick < expireTime);        // 等待延迟结束
}
```

## 3. 输出比较

### 3.1 简介

定时器通道：一个定时器（TIMx）通常有多个通道，每个通道都能利用同一个计数器 `CNT` 做自己的比较/捕获动作。

每个通道都有一个比较寄存器 `CCR1~CCR4`。硬件会实时比较：

- 当 `CNT == CCRx` 时，触发该通道对应事件。
- 然后按设置的 OC 模式改变输出参考信号 `OCxREF` ，最终作用到引脚

  > `OCxREF` = 定时器通道根据 `CNT` 与 `CCRx` 比较、再按 `OCxM` 模式处理后，生成的“内部参考电平”。

### 3.2 基本工作原理（PWM）

PWM - Pulse Width Modulation：脉冲宽度调制

一种周期固定，占空比可调的信号
通过调节占空比
等效地调节信号的输出幅度

![[tikz-timers-02.svg]]

#### 3.2.1 工作原理

1. 启动时基单元
2. 通道实时比较

![[截屏2026-02-05 下午6.07.59.png]]

- 当CNT的值小于CCR的值时，输出高电压
- 否则输出低电压
- 最终形成方波信号（PWM信号）

1. **PWM信号周期由ARR寄存器的值决定**
2. **高电压所占时间由CCR的值决定**（占空比可调的原因）

### 3.3 工作模式

#### 3.3.1 八种工作模式

| OCxM模式（常见8种） | 模式名                              | 匹配条件（`CNT == CCRx`）时的行为                            | `OCxREF`典型变化特点     | 常见用途                          |
| ------------------- | ----------------------------------- | ------------------------------------------------------------ | ------------------------ | --------------------------------- |
| `000`               | Frozen（冻结）                      | 匹配时不对输出参考信号做改变                                 | 保持原状态不变           | 只关心比较事件/中断，不改引脚波形 |
| `001`               | Set active on match（匹配置有效）   | 一旦匹配，将 `OCxREF` 置为有效电平                           | 到匹配点后变为有效并保持 | 单次到点置位控制                  |
| `010`               | Set inactive on match（匹配置无效） | 一旦匹配，将 `OCxREF` 置为无效电平                           | 到匹配点后变为无效并保持 | 单次到点清零控制                  |
| `011`               | Toggle（匹配翻转）                  | 每次匹配都翻转 `OCxREF` 电平                                 | 匹配一次翻转一次         | 产生可控翻转波形/分频输出         |
| `100`               | Force inactive（强制无效）          | 与匹配无关，强制输出无效电平                                 | 恒为无效                 | 调试、保护态、强制关断输出        |
| `101`               | Force active（强制有效）            | 与匹配无关，强制输出有效电平                                 | 恒为有效                 | 调试、测试、强制拉高输出          |
| `110`               | PWM mode 1                          | 向上计数时：`CNT < CCRx` 有效，`CNT >= CCRx` 无效（常见描述） | 周期内“先有效后无效”     | 标准PWM输出（电机/LED/舵机）      |
| `111`               | PWM mode 2                          | 向上计数时：`CNT < CCRx` 无效，`CNT >= CCRx` 有效（常见描述） | 周期内“先无效后有效”     | 与PWM1互补逻辑场景                |

**PWM1是最常见的工作模式**

PWM 模式 1 与模式 2 的波形对比（两者互为反相）：

![[tikz-timers-03.svg]]

### 3.4 互补输出

同一个通道会同时给出两路相关波形：

- 主输出：`CHx`
- 互补输出：`CHxN`（参考信号经过一个反向器）

两路逻辑互补（可理解为一高一低的对应关系）。死区时间保护机制 #待补充

### 3.5 极性选择

极性选择是：

> **“内部有效电平”最终映射到引脚时，是不反相输出，还是反相输出。**

- 极性位决定：`OCxREF` 到外部 `CHx/CHxN` 时要不要取反
- 所以“有效电平”不一定等于“GPIO高电平”，这取决于极性配置。

## 5. 输入捕获

### 5.1 基本原理

> 输入捕获就是“外部信号一到边沿，立刻把当前 CNT 时间戳拍下来”。

是一种**硬件打点**。

1. **极性选择**：指定抓上升沿、下降沿或双边沿
2. **捕获动作**：一旦满足条件，把当前 `CNT` 复制到 `CCRx`

所以 `CCRx` 里存的不是“电平”，而是**事件发生时刻的计数值**。

### 5.2 内部结构

![[截屏2026-02-06 上午9.15.52.png]]

#### 5.2.1 输入滤波

可选，去毛刺/抗抖，得到纯净信号

不用滤波时，抖动会直接变成测量误差

#### 5.2.2 边沿检测

边沿检测决定— **“到底在信号的哪个瞬间按下快门，把 CNT 存进 CCRx？”**

输入信号 `TIx` 进来后，先可经过滤波器（去毛刺），再进入边沿检测单元。当检测到配置的目标边沿时，硬件立即触发捕获：

$$
CCRx \leftarrow CNT
$$

#### 5.2.3 信号选择

通道 `CCx` 的输入源通常可选为：

- **直接映射（DirectTI）**：`ICx` 选本通道对应引脚 `TIx`
- **间接映射（IndirectTI）**：`ICx` 选对侧引脚 `TIy`

间接输入适合 **PWM 输入模式**：同一路外部 PWM，经通道交叉后可同时抓周期与脉宽（一个抓上升沿，一个抓下降沿）。可以节省引脚

#### 5.2.4 分频器

**分频器（IC Prescaler）**，是一个“**边沿计数门槛器**”。

一句话定义：

> 不一定每次检测到边沿都捕获，而是“每第 N 次边沿才捕获一次”。

## 7. 从模式控制器

> 从模式控制器就是让“本定时器 CNT 怎么跑”受外部/其它定时器触发信号指挥的模块。

### 7.1 从模式和主模式

| 模式名                 | 核心作用                                          | 典型场景                   |
| ---------------------- | ------------------------------------------------- | -------------------------- |
| Disabled（关闭从模式） | 不使用从模式控制器，CNT按内部时钟正常计数         | 普通定时/PWM基础用法       |
| Encoder Mode 1         | 编码器模式1：只用TI1边沿计数，方向参考TI2电平     | 旋转编码器测速/定位        |
| Encoder Mode 2         | 编码器模式2：只用TI2边沿计数，方向参考TI1电平     | 旋转编码器测速/定位        |
| Encoder Mode 3         | 编码器模式3：TI1和TI2边沿都参与计数（四倍频常用） | 高分辨率编码器读取         |
| Reset Mode             | 触发事件到来时，CNT被复位（重置）                 | 周期对齐、事件到来清零计时 |
| Gated Mode             | 触发信号有效时才允许计数，无效时暂停              | 测脉宽、测有效窗口时间     |
| Trigger Mode           | 触发事件到来后启动计数（一次启动）                | 外部事件触发延时/定时      |
| External Clock Mode 1  | 外部触发脉冲作为计数时钟源（而非内部时钟）        | 外部脉冲计数、频率累计     |

### 7.2 Enable 主模式（常写作 `TRGO = Enable`）

核心：把 **CEN（计数器使能位）** 作为触发输出条件。

### 7.3 Update 主模式（`TRGO = Update`）

核心：每次**更新事件 UEV**发生时输出 TRGO。

## 8. PWM 参数测量原理

### 8.1 TRGI 来源

**从模式控制器**里，`TRGI`（Trigger Input）不是固定一根线，而是由 `TS` 位（触发选择）从多路信号里“选一路”进来。

| TRGI来源类别        | 具体来源                    | 说明与典型用途                                               |
| ------------------- | --------------------------- | ------------------------------------------------------------ |
| 内部触发（ITR）     | `ITR0 / ITR1 / ITR2 / ITR3` | 来自其他定时器的 TRGO（主定时器输出）。用于定时器级联、同步启动、同步复位。不同 TIM 的 ITR 映射关系要查参考手册。 |
| 通道输入滤波后信号1 | `TI1FP1`                    | TI1 经极性选择/滤波后的触发信号。常用于外部引脚触发从模式动作（复位/门控/触发启动等）。 |
| 通道输入滤波后信号2 | `TI2FP2`                    | TI2 经极性选择/滤波后的触发信号。用途同上，常与 TI1 互补选择。 |
