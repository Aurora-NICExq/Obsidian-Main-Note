# I2C

> [!summary] 核心结论
> I2C 用 **SCL + SDA** 两根线实现**一主多从**，从机靠 7 位地址区分。两根线都是**开漏 + 上拉**，因此天然实现**逻辑线与**：任一设备拉低即为低，全部释放才是高——这也是"发送方"其实是"谁不写 1"的原因。数据**高位先行**，每传完一个字节接收方要给 **ACK**。读多个字节时，**最后一个字节必须回 NACK 再发 STOP**，否则总线会卡死。

## 1. 基本电路结构

USART 串口只能实现一对一通信，I2C 可以实现一对多数据传输

高位先行

### 1.1 I2C 总线电路结构

![[截屏2026-02-01 上午10.27.42.png]]

- 总线主要由SCL和SDA两根线组成
- 被连接的设备是从机，从机有7位地址，最多连接设备数量为可分配的地址数

### 1.2 数据线和总线

SCL 传输时钟信号，SDA 传输数据信号

![[tikz-i2c-01.svg]]

1. 时钟信号由主机发送给从机
2. 数据信号通信方向可以是双向的
3. 时钟信号的每一个周期，数据线传输一位数据

### 1.3 逻辑线与

以硬件电路的形式来实现逻辑与运算

- SCL全部写1时，输出高阻抗，上拉电阻把悬空导线拉到高电压
- SCL其中一个引脚写0时，SCL总线接地，输出低电压

### 1.4 主机发送时钟信号

1. 从机的SCL引脚写1（相当于从电路上断开），控制主机的SCL引脚交替写1和0。

### 1.5 主机发送数据

从机的SDA引脚写1（相当于从电路上断开），控制主机的SDA引脚交替写1和0输出高低电压。

### 1.6 从机发送数据

除了通信的从机之外写1，通信的从机SDA交替写1或者0。

1. 起始位：SCL为高电压，SDA中出现一个下降沿

### 2.3 寻址

位于起始位后，数据传输开始前。

RW# 是方向位，判断是读还是写（W 为 0，R 为 1）

### 2.4 传输数据

- 主机发送数据（发送一个字节），从机应答（ACK）
- 从机发送数据相反

## 4. I2C 写数据

### 4.1 内部结构框图

![[截屏2026-02-02 上午10.32.51.png]]

- SR1和SR2是状态寄存控制器
- SDA控制电路用来控制发送或接收波形
- 控制寄存器用来改变寄存器运行状态

### 4.2 数据发送过程

1. 起始位：START写1，模块拉低SDA，发送起始位。
2. 寻址：通过发送寄存器发送数据。
3. 等待ACK：查询状态寄存器中的标志位。
4. 停止位：STOP写1，模块拉高SDA，发送停止位。

### 4.3 函数封装

```c
int My_I2C_SendBytes(I2C_TypeDef *I2Cx, // I2C接口的名称
                     uint8_t Addr,      // 从机地址，靠左
                     uint8_t *pData,    // 要发送的数据
                     uint16_t Size      // 要发送的数据的数量（字节）
                    );
```

**作用**：通过 I2C 向从机发送若干个字节。

**返回值**：这是一个带有错误反馈的函数：

- `0`: **成功** - 发送顺利完成。
- `-1`: **寻址失败** - 发送了设备地址，但没有人应答
- `-2`: **发送的数据被拒绝** - 设备地址匹配了，但发送数据途中从机停止了应答

### 4.4 发送起始位

```c
// #2. 发送起始位
I2C_GenerateStart(I2Cx, ENABLE); // 向硬件发出“开始”指令

while(I2C_GetFlagStatus(I2Cx, I2C_FLAG_SB) == RESET); // 死循环等待，直到起始位真正发出去
```

1. **START (发送起始位)**：
   - 这是一个控制位。当你向它写 `1` 时，硬件电路会在 I2C 总线上产生一个“起始条件” (SCL 高电平时 SDA 由高变低)。
2. **SB (起始位发送完成)**：
   - 这是一个状态标志位。
   - **0**：起始位还没发出去（或者还没发完）。
   - **1**：起始位已经成功发送完成了。

### 4.5 发送地址

**标志位：**

1. **AF (Acknowledge Failure - 应答失败)**：
   - **1**：表示未收到 ACK（即收到了 NACK）。通常意味着“找不到设备”或者“设备没准备好”。
2. **ADDR (Address Sent - 寻址成功)**：
   - **1**：表示地址发送完毕，并且收到了从机的 ACK 应答。

```c
// #3. 发送地址

// 3.1 清除之前的错误标志（好习惯）
I2C_ClearFlag(I2Cx, I2C_FLAG_AF);

// 3.2 发送地址 + 写方向(RW# = 0)
// 注意：& 0xFE 是为了强制将最低位变0，表示“写”操作 ｜Addr是从机的地址
I2C_SendData(I2Cx, Addr & 0xfe);

// 3.3 等待结果（双重检查）
while(1){
    // 情况A：寻址成功 (收到ACK)
    if(I2C_GetFlagStatus(I2Cx, I2C_FLAG_ADDR) == SET)
        break; // 跳出循环，继续后续发送

    // 情况B：寻址失败 (收到NACK/未收到ACK)
    if(I2C_GetFlagStatus(I2Cx, I2C_FLAG_AF) == SET){
        I2C_GenerateStop(I2Cx, ENABLE); // 发送停止位，释放总线
        return -1; // 返回错误代码 -1 (对应之前定义的“寻址失败”)
    }
}
```

#### 4.5.1 清除 ADDR

```c
// 清除ADDR (先读SR1，再读SR2)
I2C_ReadRegister(I2Cx, I2C_Register_SR1);
I2C_ReadRegister(I2Cx, I2C_Register_SR2);
```

### 4.6 发送数据

```c
for (uint16_t i=0;i<size;i++){
}
```

检查标志位，防止数据覆盖

```c
// 等待发送数据寄存器空
while(1){
    // 检查是否收到 NACK (对方拒绝接收)
    if(I2C_GetFlagStatus(..AF..) == SET){
        I2C_GenerateStop(...); // 发送停止位
        return -2; // 返回错误码 -2 (发送的数据被拒绝)
    }

    // 检查 TDR 是否为空 (可以发下一个字节了吗？)
    if(I2C_GetFlagStatus(..TxE..) == SET) 
        break; // 跳出等待，准备写数据
}
```

- 代码一旦发现 `AF == SET`，立即发送 STOP 信号终止通信，并返回 **`-2`**。这正好对应了最开始函数定义中的错误码说明：**“-2: 发送的数据被拒绝”**。
- `TxE = 1` 表示硬件的缓冲区空了，程序可以把下一个字节放进去了。

BTF 标志位检查

```c
if(I2C_GetFlagStatus(..BTF..) == SET)  //BTF为1代表数据的发送完成
        break;
```

### 4.7 发送停止位

STOP 位置 1

```c
// 发送停止位
I2C_GenerateStop(I2Cx, ENABLE); 

// 返回成功状态
return 0;
```

## 5. I2C 读数据

### 5.1 编程接口

```c
int My_I2C_ReceiveBytes(I2C_TypeDef *I2Cx, // I2C接口的名称
                        uint8_t Addr,      // 从机地址，靠左
                        uint8_t *pBuffer,  // 接收缓冲区
                        uint16_t Size      // 要接收的数据数量
                       );
```

**作用**：通过 I2C 总线从指定的从机读取若干个字节的数据，并存入 `pBuffer` 指向的数组中。

**返回值**：

- `0`: **读取成功**。
- `-1`: **寻址失败** - 发送地址后无人应答。

### 5.2 数据读取过程

接收中间的字节时，主机要给从机发 ACK。

**关键点**：接收**最后一个**字节时，主机必须发 **NACK**，然后紧接着发 STOP 信号。如果这一步做错，从机可能会继续霸占总线，导致通信卡死。

### 5.3 发送起始位和地址

- **START** - 发送起始位：向该比特位写 1 发送起始位
- **SB** - 起始位发送完成：
  - `0` - 起始位未发送
  - `1` - 起始位发送完成

### 5.4 发送 ACK 和 NACK

ACK 只作用于正在被接收的字节

### 5.5 发送停止位

停止位在当前字节接收完才会被发送

### 5.6 Size 值

```c
if(Size == 1){

    // 清除ADDR
    I2C_ReadRegister(I2Cx, I2C_Register_SR1);
    I2C_ReadRegister(I2Cx, I2C_Register_SR2);
    // 向ACK写0
    I2C_AcknowledgeConfig(I2Cx, DISABLE);
    // 发送停止位
    I2C_GenerateStop(I2Cx, ENABLE);
    // 等待RxNE置位
    while(I2C_GetFlagStatus(I2Cx, I2C_FLAG_RXNE) == RESET);
    // 读取数据
    pBuffer[0] = I2C_ReceiveData(I2Cx);
}
```

### 5.7 OLED 显示屏

从 OLED 显示屏中读数据，

D6 = 0，表示屏幕开启，D6 = 1，表示屏幕关闭

```c
uint8_t rcvd;

My_I2C_ReceiveBytes(I2C1, 0x78, &rcvd, 1);

if((rcvd & (0x01<<6)) == 0){    // 检测到屏亮
    GPIO_WriteBit(GPIOC, GPIO_Pin_13, Bit_RESET);    // 亮
}else{    // 检测到屏灭
    GPIO_WriteBit(GPIOC, GPIO_Pin_13, Bit_SET);      // 灭灯
}
```

## 6. 软件 I2C

原理：用两个普通 GPIO 引脚，按 I2C 的时序规则去“手动”拉高/拉低，从而模拟出 SCL（时钟线）和 SDA（数据线）的电平变化
