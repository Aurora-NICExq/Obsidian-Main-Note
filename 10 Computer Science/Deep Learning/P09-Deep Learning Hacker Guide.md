# P09 深度学习黑客指南：把系统跑起来的经验法则

## 0. 讲座风格声明
这讲和前面不一样：更少公式，更像一份“从业者经验清单”。讲者强调内容是带观点的启发式，不保证所有人同意，但来自长期实践积累。

讲座目标覆盖：
- 构建数据与模型的运行系统
- 选择优化器、建立评估框架
- 有效利用计算资源
- 以及大量“你踩过坑就懂”的调试建议

## 1. 第一原则：看数据（真的看）
讲座花了大量篇幅强调：很多问题不是模型问题，而是数据问题；即便是模型问题，也常常要从数据里才能看出来。

可操作建议：
- **可视化数据**：不要只看单一指标曲线，尽量用更高维的方式理解数据。
- **和数据点做朋友**：去理解数据是怎么来的、为什么会长这样（讲者还举了“去拍照理解视觉数据”的故事）。
- 常见数据坑：
  - 类别不平衡（例如 99% 都是良性）
  - 数据偏差（bias）
  - 数据泄露（答案被“藏”在输入里）

## 2. 在正确的位置检查数据：不要只信数据加载器
讲座给了非常具体的工程建议：**检查数据的“最佳位置”是在你把数据喂进模型前**，而不是数据刚被 loader 读出来时。

典型坑位示例：
- 你以为数据在 0~1，但实际上是 0~255
- 你以为维度/reshape 没问题，但其实把输入张量形状弄错了

## 3. 评估框架：先知道“随机水平”长什么样
讲座强调要对损失/指标的数量级有常识，才能快速定位 bug：
- 分类任务里，随机猜测的 log-loss 有典型尺度（讲座用十分类的 `log(0.1)` 讨论“随机水平”）
- 回归最小二乘损失不该是负数；如果出现离谱负值，大概率是实现 bug

这类“量纲常识”是快速排错的核心工具。

## 4. 归一化：数据归一化、RMS 归一化、层归一化
讲座把归一化当作“数据与优化之间的桥”来讲：
- 你需要了解数据范围、分布形状
- 有时需要把数据压到更标准的分布

讲座还对几种归一化做了区分（复习要点）：
- RMS 归一化：把向量按均方根缩放到单位尺度
- 层归一化（LayerNorm）：先减均值再做 RMS 类缩放
- 批归一化（BatchNorm）的坑：**批量大小为 1 时不要用**（讲座给了具体反例：batch size=1 的 BN 会把单个样本减均值，导致行为很奇怪；并指出 BN 强依赖 batch size）

## 5. 数据增强（Augmentation）：最省钱的归纳偏置
讲座对数据增强的态度非常鲜明：它简单、粗暴，但往往有效。

几个关键观点：
- 数据增强是在数据层面做变换，迫使模型对某些变换“不变”
- 讲者认为它是处理大量不变性需求的最佳方式之一
- 一个更“黑客”的建议：**逐步增加数据难度**，让模型一直处在“刚好能学到点新东西”的状态，而不是把计算浪费在过简单或过难的区域

## 6. 训练过程经验：学习率、批量大小、EMA
讲座在后段给出一些训练层面的经验提醒：
- “总是要调整学习率”，通常还要调整 batch size
- 用 EMA（指数移动平均）平滑训练过程/统计量：本质是用衰减因子把新旧值混合，减少噪声，让曲线更可读、更稳定

EMA 的最常见写法就是：
```text
s_t = β s_{t-1} + (1-β) x_t
```
`β` 越大，平滑越强，响应越慢。

## 7. 朴素但强的基线：简单模型更容易构建、调试、共享
讲座强调基线的重要性：
- 简单模型更容易排错
- 你需要能解释“为什么它应该工作/为什么它不工作”
- 也更容易在团队里共享复现

## 8. 复习清单（当你训练卡住时按顺序排查）
1. 我真的看过数据吗？（可视化、抽样、分布、异常值）
2. 输入的单位/范围/形状是否和我以为的一样？（在模型入口检查）
3. 指标/损失的数量级是否合理？随机水平是多少？
4. 归一化策略有没有踩禁忌（batch size=1 还用 BN 等）？
5. 数据增强是否合理？是否能把“需要的不变性”写进训练？
6. 学习率与 batch size 是否调过？曲线是否需要 EMA 来读？
